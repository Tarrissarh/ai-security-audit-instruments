# Установка v5 для OpenCode, DeepSeek Harness, Claude Code, Codex и Cursor

## Принцип

Копируй **каждый** из 11 каталогов (`audit-*` и `ai-tool-generator`) с `SKILL.md` и его `references/` **как единый пакет** под один поддерживаемый корень Skills. Не копируй один файл SKILL.md отдельно, не переименовывай каталог без корректировки `name`.

| Платформа | Проектный путь | Особенности |
|---|---|---|
| OpenCode | `<project>/.opencode/skills/` | Можно `<project>/.agents/skills/`; нужны разрешения на `skill` tool |
| DeepSeek Harness | `<project>/.dsh/skills/` | Или `.agents/skills/`, но **только при смонтированных registry+filesystem provider+skill consumer** |
| Claude Code | `<project>/.claude/skills/` | Нативные `/skill-name`; дополнительные frontmatter возможности платформенные |
| Codex | `<project>/.agents/skills/` | Прогрессивная загрузка, Sandbox может запретить запись |
| Cursor | `<project>/.cursor/skills/` | Или `.agents/skills/`; облачные агенты не всегда видят локальные user Skills |

Если один проект использует несколько клиентов, удобна единая `.agents/skills/` **для OpenCode / DeepSeek Harness / Codex / Cursor** (при соблюдении их условий). Claude Code устанавливай отдельно в `.claude/skills/`; оба каталога могут сканироваться некоторыми клиентами, поэтому **проверяй дубликаты** и приоритет источников.

**Скиллы не являются плагинами, запускающимися в фоне.** Даже при наличии каталога хост может не предоставлять прямого делегирования. Оркестратор явно различает `SKILL_CALL` и `READ_INSTRUCTIONS`.

## Шаги

1. Распакуй ZIP. Перенеси содержимое каждого `audit-*/` и `ai-tool-generator/` внутрь выбранного проекта Skills root.
2. Проверь, что корни `skills/<name>/SKILL.md` распознаются; для DSH убедись в конфигурации пакетов Skill provider и consumer.
3. Запусти собственную статическую проверку комплекта: `python scripts/validate_skills.py .` из извлечённого каталога (никаких установок/сетевых запросов не делает).
4. В клиенте вручную выбери/укажи `audit-workflow`, передай небольшой безопасный тестовый Skill и права на выбранную папку отчёта. Проверь `docs/workflow-status.md`.
5. Пройдись по [TESTING.md](TESTING.md) для каждого клиента, где планируешь использовать пакет.

## Команды пользователя

Полный аудит: «Используй `audit-workflow`: проверь `./candidate` и сформируй отчёты/переводы; никаких исправлений исходников».

Отдельная генерация: «Используй `ai-tool-generator` и создай отсутствующий инструмент `X` по карточке `TOOL-001` для **[название хоста]** в `./generated/X`; не устанавливай и не запускай его».

Обновление: «Используй `audit-modernize` и проверь версии через официальные источники; ничего не меняй».

## Права, безопасность и OSV

- Только чтение на время аудита; записи разрешать лишь для отчётного каталога и резервных копий.
- Не давай генератору права на автоматическую установку/запуск; `disable-model-invocation: true` дополняет, но не заменяет проверку человеческого запроса.
- Не разрешай запуск тестов исследуемого инструмента без отдельного согласия.
- Для локальной OSV поддерживай `vulndb/osv` с нативными разделителями ОС; при отсутствии/старении базы не скачивай автоматически.
