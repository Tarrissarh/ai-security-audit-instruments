# Предложения по дальнейшему развитию после v5

## P0: реальные E2E-тесты клиентов

Провести испытания OpenCode, DeepSeek Harness, Claude Code, Codex, Cursor с версиями и логами. Отдельно проверить DSH mounts, Cursor Cloud, запреты на запись и ограничения модели. Сегодня v5 содержит статические тесты и документированные ручные сценарии, но не утверждает фактическую совместимость.

## P1: программируемый orchestration runner (необязательный)

Когда понадобится гарантированный контроль переходов вместо текстовых инструкций, создать отдельный доверенный CLI/плагин с JSON-state machine и минимальными правами. Skill сам по себе не универсальный планировщик и не может гарантировать API другого клиента.

## P1: eval-suite

Добавить репозиторий с безопасными фикстурами уязвимых инструкций, ожидаемыми finding IDs и проверкой полноты/точности на каждом клиенте. Вся динамика — только на искусственных данных.

## P2: структурированный отчёт

Добавить сериализацию `audit-results.json` по контракту для дальнейшего сравнения версий и дельта-аудитов. Отдельно учитывать `confidence`, `verified_at`, `source_url`, `client_version`.

## P2: внедрение и версионирование

Добавить пакет менеджмента Skills с dry-run, проверкой конфликтов и атомарной установкой только по команде человека. Задать семантические версии скиллам в `metadata.version` при следующем выпуске и сформировать changelog по каждому.

## P3: сокращение контекста

Перенести длинные профильные перечни из SKILL.md в `references/` для уменьшения загрузки контекста, когда будет проверено поведение пяти клиентов.
