# Переносимость: Windows и Linux

## Область проверки

Проверяется **локальный код комплекта**, а не реальные LLM-клиенты. Поддерживаются Python 3.11 и 3.13 в CI. Установка и запуск в OpenCode, DeepSeek Harness, Claude Code, Codex и Cursor по-прежнему **не подтверждены**.

| Область                                               | Linux (локальная среда сборки)            | Windows (NTFS)                               |
| ----------------------------------------------------- | ----------------------------------------- | -------------------------------------------- |
| Синтаксис Python и структурная валидация              | Проверено                                 | CI настроен; не запускался здесь             |
| Имена файлов Windows, в том числе `CON.md`, `COM¹.md` | Проверено моделированием ограничений      | CI настроен; не запускался здесь             |
| Коллизии регистра и Unicode NFC/NFD                   | Проверено на безопасных тестовых примерах | CI настроен; не запускался здесь             |
| UTF-8, BOM, CRLF, Unicode                             | Побайтовое сохранение проверено           | CI настроен; не запускался здесь             |
| Перезапись файла `read-only`                          | Проверено локально                        | CI настроен; не запускался здесь             |
| Резервные копии и отказ от перезаписи                 | Проверено локально                        | CI настроен; не запускался здесь             |

| Файловые операции на NTFS с ACL и блокировками        | Не применимо                              | `NOT_TESTED`                                 |
| Реальная загрузка скиллов в AI-клиентах               | `NOT_TESTED`                              | `NOT_TESTED`                                 |

## Механизмы обеспечения переносимости

- `scripts/portable_names.py` и `skills/audit-docs/scripts/portable_names.py` проверяют зарезервированные имена устройств Windows, недопустимые символы, завершающие точки и пробелы, длину UTF-16 и потенциальные коллизии нормализации Unicode/регистра и символические ссылки/NTFS reparse points.
- `scripts/platform_compat.py` проверяет имена всех компонентов исходного `skills/` **до установки**, а также неоднозначные пути в целевом проекте.
- `skills/audit-docs/scripts/safe_writer.py` проверяет имена каталогов и файлов отчёта до записи. Перезапись файлов без права записи владельца блокируется; операция снимает защиту с файла **только вручную пользователем**, а не автоматически.
- Оба Python-модуля правил имён намеренно одинаковы: установленный `audit-docs` может работать автономно без корневого каталога `scripts/`.
- Проверочные сценарии находятся в `tests/test_portability.py`.

## Локальные команды

Linux/macOS:

```sh
python3 -m pip install -r requirements-validation.txt
python3 scripts/validate_skills.py .
python3 -m unittest discover -s tests -v
python3 scripts/platform_compat.py smoke --platform claude-code
```

Windows PowerShell (из корня распакованного пакета):

```powershell
py -3 -m pip install -r .\requirements-validation.txt
py -3 .\scripts\validate_skills.py .
py -3 -m unittest discover -s tests -v
py -3 .\scripts\platform_compat.py smoke --platform claude-code
```

Все сценарии не запускают код аудируемых инструментов. Зависимости устанавливаются только по отдельной команде пользователя.

## CI

Файл `.github/workflows/portability.yml` запускает тесты на `ubuntu-latest` и `windows-latest` с Python 3.11/3.13. Для начала автоматических испытаний необходимо поместить полный комплект в GitHub-репозиторий и включить GitHub Actions. **В текущей среде Windows job не запускался.**

На Windows ограничения на создание символических ссылок могут зависеть от разрешений CI runner. Отклонение таких операций должно быть явно зафиксировано, а не считаться успехом. Символьные ссылки при публикации и установке по умолчанию запрещены.

## Ограничения

- Имена Windows проверяются до создания файлов, но окончательное поведение зависит от фактического тома, драйвера и настроек NTFS/SMB.
- Нельзя гарантировать защиту от параллельного враждебного процесса, меняющего каталоги во время записи; используйте выделенный доверенный каталог.
- Нельзя делать вывод о работе AI-клиента только по успешному копированию Skill в его каталог.
