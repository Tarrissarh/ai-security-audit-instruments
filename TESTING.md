# Проверка качества и совместимости v5

## A. Статическая проверка комплекта

Из корня распакованного комплекта (только Python stdlib, не обращается к сети):

```shell
python scripts/validate_skills.py .
python -m unittest discover -s tests -v
```

Проверяются наличие 11 Skills, корректные поля frontmatter, совпадение имён, дубли ID, локальные Markdown-ссылки, наличие платформенных адаптеров, явный human-only guard у генератора и отсутствие циклических downstream-вызовов в оркестраторе. Это **не** проверяет клиенты и не запускает исследуемый код.

## B. Интеграционные сценарии (запускать вручную в каждом клиенте)

Для OpenCode, DeepSeek Harness, Claude Code, Codex и Cursor повтори каждый сценарий:

1. **Discovery:** установи все каталоги, убедись, что `audit-workflow` и шесть аудиторов обнаружены. В DSH проверь provider+consumer; в Cursor Cloud убедись, что файлы доступны агенту.
2. **Read-only:** предоставь тестовый Skill с безвредным содержимым; проверь, что исходник не менялся; shell исследуемого объекта не запускался.
3. **Orchestration:** явно запусти `audit-workflow`; запроси стадии audit/improve/modernize/docs. Проверь метод (`SKILL_CALL` либо `READ_INSTRUCTIONS`) и фактические файлы.
4. **Documentation:** проверяй `README.md`, `docs/workflow-status.md`, `docs/**/*.md` при больших отчётах и `translations/**/*.md` для имеющихся оригиналов. Нет пустых/битых ссылок.
5. **Missing tool:** добавь в тестовый Skill упоминание `missing-test-tool`, не устанавливая его. Ожидай карточку зависимости, **никаких автоматически сгенерированных файлов**.
6. **Manual generator:** отдельно запроси генерацию в `./generated/sandbox-test-tool`. Ожидай новые файлы только внутри каталога, без подключения или запуска.
7. **No-write:** запрети запись в выходной каталог. Ожидай `WRITE_UNAVAILABLE`, а не ложное сообщение о создании файлов.
8. **No-web:** отключи веб-доступ. Ожидай `UNVERIFIED` для новейших версий, а не вымышленные ссылки.
9. **Permissions:** заблокируй загрузку одного из скиллов. Ожидай `BLOCKED/SKIPPED` и ограниченный отчет, а не обход разрешений.
10. **OSV:** база отсутствует/старше недели. Ожидай запрос разрешения на загрузку, а не автоматическую загрузку.

Фиксируй для каждого хоста: `client_version`, `environment`, `test_case`, `observed_result`, `pass/fail`, `logs_path`, `notes`. Без этих данных нельзя утверждать подтверждённую полную совместимость.

## C. Критерии публикации

- Все локальные статические тесты проходят.
- Все 11 Skills загружаются хотя бы в одном проверяемом хосте и явно задокументированы ограничения других.
- Генератор не исполняется автоматически при аудите.
- Отчётное дерево создаётся без потери информации и изменений оригинального кода.
- Не обнаружен несанкционированный сетевой доступ при статическом аудите.
