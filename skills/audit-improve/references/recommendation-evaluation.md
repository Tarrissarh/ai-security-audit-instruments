# Оценка рекомендаций

Каждая рекомендация должна иметь: точное `finding_id`, ссылку на доказательство, `change`, `rationale`, `priority`, `compatibility`, `validation` и `rollback`.

Отдельно проверь:

1. Предлагаемый шаг устраняет **подтверждённую**, а не придуманную проблему.
2. Есть вариант минимального исправления, а не безосновательный переписываемый проект.
3. Встроенные функции платформы рассматриваются до разработки собственного механизма.
4. Рекомендация не изменяет источник автоматически; исправление только по явному запросу.
5. Не требуется запускать исследуемый код или скачивать зависимости для доказательства словесной рекомендации.
6. Для спорных альтернатив честно указан `UNVERIFIED` и метод уточнения.
7. Указана регрессия: что именно может перестать работать, как проверить и откатить.

В полном пакете `quality/scripts/evaluate.py` проверяет **структурную** привязку рекомендации к находке. Он не проверяет инженерную целесообразность изменения; её оценивает человек по этим семи пунктам. Не выдавай статическую рубрику за выполненное тестирование.
