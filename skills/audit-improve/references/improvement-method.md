# Методика audit-improve

## 1. Что считать улучшением

Рекомендация полезна лишь если есть: **факт/источник → причина → конкретное изменение → ожидаемый эффект → способ проверки**. Разделяй дефекты, риски, возможности оптимизации и личные предпочтения. Если факт неизвестен, помечай `HYPOTHESIS`.

## 2. Матрица приоритета

| Приоритет | Основание                                     | Пример                                        |
| --------- | --------------------------------------------- | --------------------------------------------- |
| P0        | Подтверждённая критическая уязвимость/поломка | Возможность без подтверждения изменять данные |
| P1        | Значимый дефект/существенный риск             | Доступ с избыточными правами                  |
| P2        | Улучшение архитектуры/производительности      | Повторение токеноёмких инструкций             |
| P3        | Опциональный DX/рефакторинг                   | Уточнение описания                            |

Оценка серьёзности проблемы и приоритет исполнения — **разные** характеристики: высокий риск при неизвестной эксплуатации может требовать отдельной проверки до конкретного изменения.

## 3. Готовая карточка изменения

```text
ID: IMP-001
Проблема и статус: ... VERIFIED/INFERRED/UNVERIFIED
Оригинал: относительный/путь:строки ...
Категория: ...
Сейчас: ...
Изменить: ...
Пример до: ...
Пример после: ...
Почему это лучше: ...
Ожидаемый эффект: ...
Совместимость / цена / риск: ...
Критерий приёмки: ...
Способ отката: ...
Приоритет: P0/P1/P2/P3
Уверенность: высокая/средняя/низкая
```

## 4. Направления

- **Безопасность:** prompt injection, ограничение полномочий, данные и секреты, человек в контуре.
- **Надёжность:** параметры, ошибки, retry/backoff, тайм-ауты, проверка результата.
- **Эффективность:** объём контекста, дублирование, неоправданные LLM-вызовы, производительность.
- **Архитектура:** связность компонентов, простой интерфейс, минимальные зависимости.
- **Сопровождение:** версии, tests, changelog, документация, платформенная совместимость.
- **Полезность:** недостающие сценарии с подтверждённой потребностью, а не расширение ради расширения.

## 5. Минимальный пакет и проверка

Предлагай сперва изменения с высокой пользой и низкой ценой, группируй совместимые задачи. Для больших изменений — отдельный migration plan, миграционные тесты и rollback. Если план требует создать ещё один AI-инструмент, передай человека к `ai-tool-generator` **только как предложение**. По завершении любого согласованного изменения рекомендован повторный профильный аудит.
