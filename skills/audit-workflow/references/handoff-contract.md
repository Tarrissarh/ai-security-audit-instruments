# Контракт передачи результатов: JSON Checkpoints

## Идентификация и хранение

Доступны **два режима**:

1. **PERSISTENT** — разрешён доступ к доверенному Python 3.10+, установлен `jsonschema` и `markdown-it-py`, разрешена запись в согласованный `<TARGET>/audit/`. Используй [workflow_state.py](../scripts/workflow_state.py). Данные этапов сохраняются на диск и валидируются по [stage-result.schema.json](../schemas/stage-result.schema.json) и [manifest.schema.json](../schemas/manifest.schema.json).
2. **MANUAL** — среда не предоставляет Python, требуемые библиотеки или доступ к файлам. Используй структуру ниже в контексте сеанса и в отчёте, но помечай `PERSISTENCE_UNAVAILABLE`. **Не утверждай**, что можно восстановить этапы после завершения сеанса.

Все строки `run_id` бери из _фактически созданного_ `state/manifest.json`. Не придумывай UUID, хеши, вызовы Skills, версии, файлы или доказательства.

Входные файлы объекта аудита не передавай в сторонние API ради синхронизации. JSON хранит только проверенные метаданные, редактированные выдержки доказательств и относительные ссылки. Секреты, токены и персональные сведения **удаляй или маскируй** до записи. Если объект слишком большой или присутствуют символьные ссылки, скрипт прекращает хеширование с ясной ошибкой — не обходи ограничение молча.

## Последовательность этапов

`PREFLIGHT → AUDIT → IMPROVE → MODERNIZE → DOCS → VALIDATE → finalize`.

- Статусы этапов: `PENDING` (только manifest), `COMPLETE`, `PARTIAL`, `SKIPPED`, `BLOCKED`, `FAILED`.
- Методы: `SKILL_CALL` — подтверждённый вызов API с `invocations`; `READ_INSTRUCTIONS` — реально прочитан и применён SKILL.md; `LOCAL_ANALYSIS` — собственная проверка; `NOT_RUN` — этап не выполнялся.
- `PREFLIGHT`, `AUDIT`, `DOCS`, `VALIDATE` обязательны и **не могут быть SKIPPED**.
- `IMPROVE`, `MODERNIZE` разрешается пропустить с явной причиной и `method=NOT_RUN`.
- Вызов `ai-tool-generator` внутри этого workflow **запрещён**. Генерация — только после отдельного человеческого запроса.
- Повторная запись **совпадающего** JSON-результата возвращает `UNCHANGED` без повторного прохождения этапа. Повторная запись изменённого `COMPLETE` запрещена. После `FAILED/BLOCKED/PARTIAL` допускается одна повторная попытка (максимум две записи на этап).
- Недоступный предыдущий обязательный этап блокирует последующие. Результаты `IMPROVE` и `MODERNIZE` используют уже собранные доказательства; не запускай `AUDIT` заново.

## Обязательные поля stage JSON

```json
{
  "schema_version": "1.0",
  "run_id": "<из manifest.json>",
  "stage": "AUDIT",
  "status": "COMPLETE",
  "method": "READ_INSTRUCTIONS",
  "evidence": ["SKILL.md:12-26 — фактическое описание"],
  "output_files": [],
  "invocations": [],
  "data": { "checked_files": ["SKILL.md"], "findings": [] },
  "limitations": []
}
```

Схема проверяет обязательные ключи, типы и дополнительную структуру `data` по этапу. Для `PREFLIGHT` — `host_profile`; `AUDIT` — `checked_files` и `findings` с ID, severity, файлом и доказательством; `IMPROVE` — `proposals` с приоритетом и реализацией; `MODERNIZE` — `proposals` со статусом проверки; `VALIDATE` — `checks`, статусы `PASSED/FAILED/NOT_TESTED`.

Для `DOCS COMPLETE` передай **реально созданные** пути в `output_files`: `README.md`, обязательный `docs/workflow-status.md`, остальные `docs/**/*.md` и `translations/**/*.md`; иные пути запрещены. Каждый файл обязан существовать и быть непустым. `VALIDATE COMPLETE` дополнительно проверяет существование документов, SHA-256 всех объявленных документов, Markdown-ссылки и неизменность входного объекта. Результат `VALIDATE COMPLETE` с `FAILED` или `NOT_TESTED` внутри `checks` отклоняется.

Поля `invocations` должны соответствовать фактически выполненным штатным вызовам. Если `method` не `SKILL_CALL`, этот массив должен быть пуст. Пример вызова:

```json
"invocations": [{"caller": "audit-workflow", "callee": "audit-skill"}]
```

Скрипт отклоняет повторные programmatic-вызовы одного скилла в рамках одного аудита, циклы и обратные вызовы `audit-workflow`. Он не умеет перехватывать действия модели: **фактические ограничения прав обеспечивает клиент**.

## manifest.json и контрольные суммы

`state/manifest.json` хранит UUID запуска, время, абсолютный путь цели, тип, SHA-256 снимка исходных файлов, каталог отчётов, текущий статус, попытки каждого этапа, пути к подтверждённым JSON-артефактам, их SHA-256 и SHA-256 опубликованных Markdown.

`state/artifacts/<stage>-<attempt>.json` хранит результат этапа. Изменение такого JSON вручную после принятия определяется по контрольной сумме. Запись атомарная для каждого файла, но **не является общей crash-safe транзакцией двух файлов**: если процесс аварийно остановлен между записью артефакта и manifest, неподтверждённый артефакт остаётся неактивным. При возобновлении повторно передай тот же результат; не удаляй неподтверждённые артефакты без проверки.

Хеш исходников исключает выбранный каталог `report_dir` и обычные кэши `.git`, `node_modules`, `.venv`, `venv`, `__pycache__`, `.pytest_cache`. Эти исключения означают, что изменения исключённых каталогов **не инвалидируют** аудит. Для зависимостей используй lockfiles, спецификации версий и отдельную проверку. Символьные ссылки в целевом дереве не разыменовываются и приводят к отказу. Максимум: 10 000 исходных файлов, 256 МиБ исходного содержимого. Не называй хеш подтверждением безопасности исходников.

## Истинный статус и workflow-status.md

`state/manifest.json` — источник истины о текущем состоянии. `docs/workflow-status.md` — **снимок** на момент публикации и может показывать `VALIDATE: PENDING`. Не переписывай отчёт после `DOCS COMPLETE` без отдельной новой ревизии: хеш опубликованных документов намеренно зафиксирован. Итоговый `COMPLETE` подтверждай только `workflow_state.py finalize` и действующими файлами, а не текстом в Markdown.
