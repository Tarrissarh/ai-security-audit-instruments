# Проверка совместимости: уровни доказательств

Используй этот справочник **только при отдельном запросе о совместимости/клиентском E2E**, не при каждом обычном аудите.

## Уровни проверки

1. **DOCUMENTED** — обнаружены требования в официальной документации.
2. **CLI_PRESENT** — найден бинарник; личность и конфигурация ещё не подтверждены.
3. **LOCAL_STATIC_PASS** — скиллы размещены корректно локальным установщиком; реального загрузчика нет.
4. **CLIENT_REVIEW_REQUIRED** — предоставлены операторские журналы, ещё не проверенные независимо.
5. **CLIENT_PASS** — подтверждены реальная загрузка `SKILL.md`, справочников, действия клиента и результат независимой ревизии.

Для невыполненных испытаний оставляй `NOT_TESTED`. Для режима без подтверждённого права только на чтение — `BLOCKED_READ_ONLY_UNVERIFIED`; для повреждённых журналов — `INVALID_EVIDENCE`. Никогда не присваивай `CLIENT_PASS` по коду выхода 0, тексту модели, факту наличия файла, одному SHA-256 или синтетическому self-test.

## Что фиксировать

- Идентификатор и версию клиента, модель и способ установки.
- Имя фактически загруженного Skill и путь к `references/preflight.md`.
- Действительные события загрузчика, обращения к инструментам и способ делегирования этапов.
- Список созданных `audit/README.md`, `audit/docs/`, `audit/translations/` и состояние `subject/` до/после.
- Обезличенные журналы с хешами SHA-256, время и `run_id` теста, проверенные отдельным человеком.
- Согласие пользователя на сетевой/платный запуск и независимую оценку свидетельств.

## Ограничения и безопасность

- Для OpenCode используй подтверждённую версию `permissions`/`policies`.
- Для DeepSeek Harness один `dsh --profile headless` **не гарантирует** запрета записи, поэтому автоматический вызов без верифицированной политики блокируется.
- В Cursor `agent -p` без ограничений может менять файлы; для первого пробного запуска проверяй Ask mode.
- Для строгой безопасности нужны разрешения клиента и, при необходимости, внешняя OS-песочница. Разрешения нельзя заменить инструкциями в промпте.
- Исследуемый код не исполняй. Генератор отсутствующих инструментов запускается только по отдельной просьбе человека.

В полном пакете `integration/runtime/real_client.py` подготавливает проект, `cli_e2e.py` требует явных `--execute --consent`, `compatibility_report.py` валидирует локальные данные, `quality_bridge.py` считает метрики только по отдельным результатам всех 12 искусственных случаев, `evidence_export.py` экспортирует обезличенные сведения. Эти скрипты **не входят** в автономный установленный Skill и не подтверждают подлинность журнала автоматически.

См. [краткий протокол](runtime-test-protocol.md), а для подробной процедуры в полном архиве — `integration/runtime/CLIENT-TESTING.md`. При отсутствии установленного клиента или реального сеанса все клиентские E2E остаются `NOT_TESTED`, а качество реальных ответов — `N/A`.
