# Краткий протокол E2E в реальном AI-клиенте

Используй исключительно отдельный тестовый проект с искусственными фикстурами. Не запускай непроверенный код. Для каждой из OpenCode, DeepSeek Harness, Claude Code, Codex, Cursor записывай по отдельности:

1. Версия и способ установки клиента.
2. Наличие Skill в реальном каталоге клиента и успешность ручной активации.
3. Фактическое чтение `references/preflight.md` из установленного `audit-workflow`.
4. Статусы `AUDIT → IMPROVE → MODERNIZE → DOCS → VALIDATE` и способ (`SKILL_CALL` / `READ_INSTRUCTIONS` / `BLOCKED`).
5. Наличие и корректность `README.md`, `docs/` и `translations/`; SHA-256 исходников до/после.
6. Отсутствие автоматической генерации, возможность отдельной ручной генерации только после согласия человека.
7. Проверки без сети/записи и честные `UNVERIFIED` / `WRITE_UNAVAILABLE`.

Каждый этап без наблюдаемого исполнения или доказательства помечай `NOT_TESTED`; отсутствие права — `BLOCKED`. Не объявляй `PASS` по результатам одной только статической проверки каталогов. Полные командные примеры и шаблон свидетельств — в сопровождающем архиве, в каталоге `integration/` (не является обязательным содержимым установленного Skill).
