# Регрессионная оценка качества

Этот справочник предназначен для **тестирования разработчиками** `audit-workflow` и профильных `audit-*`, а не для автоматического запуска при проверке пользовательских инструментов.

1. Все тестовые объекты — синтетические недоверенные данные в каталоге `quality/fixtures/` полного архива. Не исполняй скрипты исследуемых объектов.
2. Для честной оценки передавай аудитору **только один объект**, а не весь каталог `quality`. Не передавай `quality/gold/` или синтетические готовые ответы.
3. Получи `findings[]` с категорией, файловым доказательством и номером строки, а также `recommendations[]` с привязкой к finding-id, приоритетом, способом проверки и отката.
4. Оцени результат офлайн `quality/scripts/evaluate.py` по инструкции `quality/README.md`, если эти файлы доступны и Python разрешён. Иначе не объявляй бенчмарк выполненным.
5. Используй precision, recall и F1 с отдельной статистикой по типам. Точность критичности и формальная полнота рекомендаций — независимые метрики.
6. Эталонные тесты не оценивают семантическую точность рекомендаций, неизвестные уязвимости, безопасность реального внедрения или фактическую совместимость хоста.

В обычном пользовательском аудите этот бенчмарк не запускается автоматически и не влияет на модель независимо от запроса пользователя. `ai-tool-generator` никогда не запускается в ходе оценки.
