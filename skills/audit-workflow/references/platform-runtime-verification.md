# Подтверждение работы в пяти AI-клиентах

**Важное разграничение:** `LOCAL_INSTALL_PASS`, `local_discovery_static=PASS`, корректный YAML и наличие бинарника клиента **не равны** подтверждённой загрузке скилла. Статус реального исполнения всегда `NOT_TESTED`, пока не получены наблюдаемые результаты именно из сеанса целевой среды.

## Безопасное определение доступности

1. Сначала прочитай [preflight.md](preflight.md) и [platform-matrix.md](platform-matrix.md). Если известна платформа, выбери один соответствующий адаптер.
2. Не считай наличие каталога `.agents/skills/` доказательством активного клиента. Для DeepSeek Harness дополнительно требуются смонтированные registry, filesystem provider и consumer.
3. При наличии разрешённого Python можно запустить **доверенный локальный** `scripts/platform_compat.py inspect --platform <id> --project <root>` из распакованного комплекта; он только читает файлы и не вызывает AI-клиент.
4. `scripts/platform_compat.py stage` по умолчанию лишь показывает план. Запись возможна исключительно с `--apply` после явной просьбы человека установить комплект. **Во время аудита не устанавливай скиллы автоматически.**
5. Для полноценной проверки выполнения AI-клиента вручную следуй [краткому протоколу](runtime-test-protocol.md). Обычный audit-workflow не запускает E2E автоматически: это отдельные прогоны с утверждёнными пользователем правами.
6. Сохраняй отдельно `discovery`, `activation`, `delegation`, `report_publishing`, `permissions`, `generator_consent`, `quality_benchmark`; неизвестное помечай `NOT_TESTED` / `BLOCKED` / `UNVERIFIED`, а не PASS.

## Порядок межскиллового вызова

Проверяй реальный доступный механизм загрузки. Если программного API нет, используй `READ_INSTRUCTIONS` и не называй это исполнением отдельного агента. Отсутствие нативного делегирования не мешает модели выполнить последовательность инструкций вручную, но такой результат требует отдельной проверки выходных файлов.

## Генератор

`ai-tool-generator` должен быть исключён из автоматического выбора, где клиент поддерживает `disable-model-invocation: true`. Это только дополнительный барьер: не создавай файлы без отдельного прямого запроса человека даже при отсутствии поддержки поля на хосте.
