# Preflight: платформа, права, корни, инварианты

## Проверка окружения

1. Определи название хоста только из доступных достоверных признаков: системная информация клиента, настройки/скрипты установки, метаданные сеанса. Наличие каталога `.claude` **само по себе не доказывает**, что запущен Claude Code. Модель DeepSeek, используемая в OpenCode, **не равна DeepSeek Harness**.
2. Установи `workspace_root`, `target_root`, `output_root`; проверь, доступны ли чтение/запись, файловый список, локальный поиск, веб-доступ, штатная загрузка Skill, исполнение проверяемых программ (по умолчанию запрещено), безопасная проверка собственных файлов.
3. Не предполагай, что другая платформа прочитает любые каталоги; выбери адаптер из `platform-matrix.md` по установленному хосту, а не по желаниям.
4. Для каждого требуемого скилла найди фактический `SKILL.md` в разрешённых клиентских корнях, затем проверь `name`, наличие и читаемость. Для DeepSeek Harness проверь, что mounted provider и `tool-skill` реально включены — папка на диске без провайдера недостаточна.
5. Зафиксируй имеющиеся права и блокировки (model-call, write, network, shell). При `permission denied` не пытайся обойти правила; представь ручные инструкции.
6. До записи определяй канонический путь, проверяй символические ссылки и выходы за целевой корень; существующие README/переводы резервируй.

## Статусы обнаружения

- `FOUND`: доступен через реестр и/или проверенный читаемый файл; укажи способ.
- `MISSING_CONFIRMED`: проверены релевантные корни и реестры без ошибок, требуемое имя не найдено.
- `NOT_DISCOVERABLE`: доступные механизмы не позволяют проверить список целиком.
- `UNVERIFIED`: неизвестны хост, корни или статус конфигурации.
- `BLOCKED`: нужны разрешения/инструменты, которых нет.

`HOST_PROFILE` минимум: `host`, `evidence`, `project_root`, `skill_roots_checked`, `can_list`, `can_read`, `can_write_docs`, `can_web`, `can_call_skill`, `can_run_own_validator`, `limitations`. Все булевы поля — наблюдаемые, не вымышленные.
