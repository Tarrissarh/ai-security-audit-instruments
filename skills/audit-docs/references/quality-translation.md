# Контроль качества переводов

## Автоматические структурные проверки

Проверяй YAML frontmatter (ключи, идентификаторы и машинно-значимые значения), кодовые блоки, placeholders, inline code, URL и Markdown-ссылки. Для переводов, хранимых на другом уровне вложенности, используй явную карту допустимых изменённых относительных путей.

В полном архиве доступен отдельный скрипт `quality/scripts/translation_lint.py`; он **не входит в runtime** скилла и не вызывается автоматически в пользовательском аудите. Он читает только указанные `--source` и `--translation`, не исполняет их содержимое.

## Ручная рубрика (каждый критерий 1–5)

| Критерий   | 1                              | 3                                   | 5                           |
| ---------- | ------------------------------ | ----------------------------------- | --------------------------- |
| Смысл      | Условия изменены               | Незначительные смысловые неточности | Условия исходника сохранены |
| Полнота    | Существенные разделы пропущены | Есть отдельные пропуски             | Всё значимое переведено     |
| Термины    | Путаются API и сущности        | Термины преимущественно верны       | Термины последовательны     |
| Инструкции | Изменено поведение             | Небольшие неоднозначности           | Поведение не меняется       |
| Навигация  | Не работает                    | Есть единичные нарушения            | Работает со всеми путями    |

Для оценки перевода требуется открыть исходник и перевод и проверять вручную; структура — лишь дополнительный сигнал. При нарушении сохранности исполняемой инструкции перевод не объявляй готовым вне зависимости от суммарного балла.

## Не смешивай перевод и модернизацию

Изменения устаревших API, «исправления» чужих инструкций и рекомендации записывай в `docs/`, а не внутри буквального перевода. Не создавай видимость, что скилл стал безопаснее благодаря одному только переводу.
