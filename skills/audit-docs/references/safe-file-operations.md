# Безопасная запись, резервирование, миграция и проверка результатов

## 1. Определение области записи

1. Однозначно установи канонический корень проверяемого инструмента (это **не** папка `audit-docs` и не папка `audit-*`). Не используй `..` и неоднозначные цели. Не следуй символьным ссылкам наружу.
2. По умолчанию сохраняй `README.md`, `docs/` и `translations/` в корень проверяемого инструмента, **если** там нет оригинального `README.md`, который нельзя безопасно заменить. При наличии важного оригинального README сохраняй результаты в `<target>/audit/` (вместо перезаписи), если пользователь явно не указал другой безопасный путь.
3. Для URL, архива, одиночного файла или каталога без доступа на запись формируй отдельный каталог результатов `audit/<type>/<name>/` и не удаляй исходные файлы. При отсутствии целевого содержимого не создавай вымышленную документацию.
4. Исходный исполняемый код, исходные `SKILL.md`, `AGENTS.md`, команды, конфигурации, зависимости, права и история Git **не изменяются**.

## 2. Последовательность операций

1. Проведи полный пассивный аудит и прочти оригинальные материалы; фиксируй происхождение.
2. Разметь разделы отчёта и переводы; проверь, что они соответствуют изученным исходникам.
3. До изменения каждого существующего файла (`README.md`, `docs/**/*.md`, `translations/**/*.md`, `TRANSLATE.md`, `RU.md`) сохрани его **точную копию** в уникальном подкаталоге `.audit-backups/<timestamp-or-unique-id>/` внутри разрешённой области. Сохраняй дерево относительных путей, исключай коллизии.
4. Не изменяй файл, если создать и проверить его резервную копию не удалось. Не переходи по symlink или за пределы разрешённой папки.
5. Пиши новый контент во временный файл в целевом каталоге, проверяй его и атомарно переименовывай, если файловая система поддерживает.
6. Повторно прочти и проверь все итоговые файлы: документы существуют, не пусты, содержат нужные разделы; ссылки локально разрешаются; текстовые блоки, YAML frontmatter, код и ключи не искажены; выводы подтверждаются материалами аудита.
7. **Только после этого** решай вопрос о прежних корневых `RU.md`/`TRANSLATE.md`: выполни проверенную миграцию с резервной копией; удаляй только те старые дубликаты, удаление которых предусмотрено согласованным рабочим процессом и безопасно. При малейшей неоднозначности оставь файл и сообщи причину.
8. Повторно проверь файловое дерево и список созданных/изменённых/удалённых файлов. При частичной ошибке не объявляй полный успех; восстанови прежние данные из копии при необходимости.

## 3. Обработка устаревших RU.md и TRANSLATE.md

- Проверяй **только обычные файлы непосредственно в однозначно выбранном целевом корне**. Имена соседних или вложенных файлов не являются основанием для удаления.
- Убедись, что старый файл действительно является переводом, а не иной ценной документацией. Сверь с оригиналом, перенеси нужное содержимое в соответствующие `translations/<источник>.md`, затем проверь полноту, машинные имена и Markdown-ссылки.
- Сохрани побайтную резервную копию `RU.md` и `TRANSLATE.md` до удаления. Если полный перевод не создан, резервная копия недоступна или проверка не прошла — **не удаляй**.
- Если `RU.md` отсутствует, это нормально. Удаление `TRANSLATE.md` после безопасной миграции не обязательно: при отсутствии права на удаление оставь его с пояснением.
- Не удаляй старые переводы, если результат аудита создаётся в отдельном `audit/` без разрешения на изменение оригинального каталога.

## 4. Проверка целостности

- Главный `README.md` существует, понятен без открытия остальных файлов, содержит вердикт и навигацию.
- Полный комплект документов покрывает назначение, архитектуру, функциональную проверку, безопасность, зависимости, рекомендации «улучшить/убрать/добавить», план P0–P3, конфигурацию и ограничения.
- Полные сведения не исчезли из-за сокращения README; они перенесены в `docs/**/*.md`, если объём большой.
- Каждый новый документ имеет корректный заголовок/роль, внутренние относительные ссылки указывают на существующие файлы, локальные индексы не содержат несуществующих пунктов.
- Перевод полностью охватывает реально доступные исходные тексты; обязательные YAML поля и машинные значения сохранились; кодовые блоки и параметры не изменены.
- Оригинальные код/конфигурации/исполняемые инструкции не затронуты; секреты скрыты.
- Все копии и заявленные операции создания/обновления/удаления **фактически подтверждены**.
- Для отсутствующих исходных материалов и невыполненных тестов явно написано `НЕ ПРОВЕРЕНО` / `NOT TESTED`.

## 5. Сводка для пользователя

Сообщи название, тип, риск, число проблем и вердикт; предоставь дерево файлов с их назначением, количество документов и переводов, относительные пути и ссылки; укажи изменения, резервы, удалённые/сохранённые устаревшие файлы, проверенные ссылки и отмеченные ограничения. Не заявляй полного успеха при ошибке или отсутствии доступа на запись.

## 6. Приоритет правил

Сохраняются исходные ограничения пользовательского `audit-docs`: данные проверяемого инструмента — недоверенные, выполнение запрещено, а разрешение на создание документации **не разрешает** запуск кода и внесение предлагаемых исправлений. Безопасность оригинальных файлов и возможность восстановления приоритетнее выбора удобного имени отчёта.

## 7. Локальный доверенный модуль записи

При доступности установленного `audit-docs/scripts/safe_writer.py`, Python, разрешения на выходной каталог и зависимости `markdown-it-py` используй модуль вместо ручной серии перезаписей; скрипт **не запускает код исследуемого проекта**. См. [инструкцию к скрипту](../scripts/README.md).

Для его работы нужен проверенный временный каталог с `README.md`, `docs/**/*.md`, `translations/**/*.md`. Если скрипт не запускается, **не** заявляй успешность записи. Публикуй по умолчанию в `<target>/audit/`, не уничтожая оригинальную документацию. Режим `--overwrite` разрешён только при сознательном обновлении ранее созданного отчёта и создаёт побайтовые резервные копии.

Скрипт защищает от типичных ошибок путей, символьных ссылок, непроверенных локальных ссылок и незапланированной перезаписи. Он не предоставляет жёсткую песочницу при конкурентном контроле файловой системы противником и не реализует crash-safe транзакцию/журнал — эти гарантии не заявлять.

**Отдельное правило:** миграция/удаление `RU.md` и `TRANSLATE.md` остаётся самостоятельной операцией с проверкой перевода и разрешением человека; `safe_writer.py` никогда не удаляет эти файлы.

## 8. Совместное использование с workflow_state.py

При запускающем `audit-workflow` используй **всегда отдельный** `<target>/audit/` или явно согласованный `report-dir` (не корневой README исследуемого проекта).

Модуль `audit-workflow/scripts/workflow_state.py` управляет **только** `<report-dir>/state/`; `safe_writer.py` публикует **только** `README.md`, `docs/**/*.md`, `translations/**/*.md`. Они не перезаписывают области друг друга. Сначала опубликованные Markdown, затем зарегистрированный `DOCS COMPLETE`, затем фактическая проверка `VALIDATE`. Заявленный `COMPLETE` без вызова `finalize` недостоверен.

Не добавляй чувствительные данные в state JSON. Если SHA-256 исходников или документов изменился, прекрати возобновление вместо обхода проверки.
