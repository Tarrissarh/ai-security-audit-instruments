# Переводы оригинальных материалов в translations/

После завершения анализа подготовь отдельные Markdown-документы с переводом оригинальных инструкций на русский язык.

**Перевод должен быть максимально точным, полным и технически корректным.**

Цель — позволить русскоязычному разработчику полностью изучить оригинальные инструкции без необходимости читать их на иностранном языке.

## Выбор источника перевода

Выбирай исходные файлы в зависимости от типа инструмента:

| Тип     | Основные источники                                                 |
| ------- | ------------------------------------------------------------------ |
| Skill   | `SKILL.md`                                                         |
| Agent   | `AGENTS.md`, описание агента, конфигурации промптов                |
| Command | Markdown-файл команды и её инструкции                              |
| MCP     | Документация сервера, описания Tools, Resources и Prompts          |
| LSP     | Документация языкового сервера, инструкции и описания возможностей |
| Hooks   | Описания событий, правила конфигурации и инструкции обработчиков   |

Если инструмент содержит несколько файлов с человекочитаемыми инструкциями, переводи их последовательно, отмечая исходный путь к каждому файлу.

Если доступен `SKILL.md` — переводи его целиком.

Если `SKILL.md` отсутствует — переводи фактически доступные оригинальные инструкции соответствующего типа.

Если имеются только исходный код или бинарные файлы без документации, не выдумывай перевод несуществующего текста. Обозначь ограничения.

## Правила перевода

1. Переводи весь доступный исходный текст, а не только краткое содержание.
2. Сохраняй исходную структуру разделов.
3. Сохраняй порядок инструкций.
4. Не удаляй требования и предупреждения.
5. Не изменяй смысл условий.
6. Не добавляй в перевод собственные рекомендации.
7. Не исправляй обнаруженные ошибки в оригинальном тексте.
8. Сохраняй Markdown-разметку.
9. Не изменяй кодовые блоки.
10. Не переводи имена переменных.
11. Не переводи имена функций.
12. Не переводи ключи JSON, YAML и TOML.
13. Не изменяй CLI-команды.
14. Не изменяй пути к файлам.
15. Не изменяй URL.
16. Не изменяй технические идентификаторы.
17. Не изменяй шаблонные переменные и плейсхолдеры.
18. Не изменяй регулярные выражения.
19. Не изменяй синтаксис вызова инструментов.
20. Не изменяй имена API и MCP Tools.
21. Не изменяй технические значения метаданных, влияющие на машинную обработку.
22. Если термин имеет общепринятое английское название, допускается оставить его рядом с русским переводом.

Например:

`Prompt Injection` — внедрение вредоносных инструкций.

`Tool Calling` — вызов инструментов.

`Least Privilege` — принцип минимальных привилегий.

Если YAML frontmatter присутствует в оригинале, сохраняй его структуру и машинно значимые значения. Переводи только человекочитаемые описания, не нарушая синтаксиса.

## Размещение и формат переводов

Каждый перевод сохраняй как `translations/<relative-path-original>`. При одном файле допустимо `translations/SKILL.md` или `translations/<имя>.md`. При нескольких переводах создавай `translations/README.md` как индекс. Следующее — пример заголовка описательной **неисполняемой** документации, а не обязательный префикс в машинно читаемом файле:

# Перевод [Название инструмента]

**Оригинальный источник:** путь к исходному файлу.

**Тип инструмента:** Skill / Agent / Command / MCP / LSP / Hooks.

**Проверенная версия:** версия или commit, если известны.

**Язык оригинала:** укажи исходный язык.

**Язык перевода:** русский.

**Примечание:** перевод предназначен для изучения и не заменяет оригинальную рабочую конфигурацию.

---

Вслед за метаданными размещай полный перевод документации с сохранением исходных разделов, заголовков, списков, таблиц и кодовых блоков. Если файл является исполняемым определением, не добавляй перед его обязательным YAML frontmatter никаких произвольных заголовков/метаданных: происхождение и язык указывай в `translations/README.md`, а сам файл начинай с оригинального синтаксиса.

Если переводится несколько документов, сохраняй **разные** файлы в `translations/` по исходным относительным путям и фиксируй соответствия в индексе, не объединяй большие оригиналы в один файл.

Не включай в файлы `translations/` результаты аудита, собственные выводы, исправления и рекомендации. Для этого используются `README.md` и `docs/`.

## Большие переводы и сохранение исполняемости

- Каждый исходный Agent/Command/Skill сохраняй одним переводом на единицу оригинала; **не** режь исполняемый файл по числу строк.
- Большие **справочные** исходники разрешено раскладывать по тематическим файлам (`translations/references/<name>/*.md`) с индексом и ссылками при сохранении логической полноты.
- Переразбиение исполняемых инструкций допускается только если платформа документированно поддерживает загрузку связанных файлов, а целостность и ссылки проверены. Иначе сохраняй цельный исполняемый перевод в одном файле независимо от объёма.
- Код, схемы, JSON/YAML ключи, параметры MCP, команды и машинные значения не переводятся. Необоснованно добавленные инструкции способны изменить поведение: фиксируй пояснения переводчика в `docs/translation-notes.md`.
- Секреты в переводе маскируй, при этом помечай отличия от оригинала; такие переводы не следует считать побайтно эквивалентными для запуска.
