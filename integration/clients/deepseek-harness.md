# deepseek-harness: ручной интеграционный тест

## Обнаружение

`.dsh/skills` либо `.agents/skills`, каталог Skill **строго одним уровнем ниже root**.

## Специальное условие

Проверь, что в конкретной композиции смонтированы registry `dsh-skill`, файловый провайдер `dsh-skill-filesystem` и модельный consumer `dsh-tool-skill`. Просто наличие CLI или `SKILL.md` недостаточно.

## Этапы для подтверждения

1. Выполни локальный `smoke` из корня пакета и запиши его JSON; это **не** E2E клиента.
2. В реальном клиенте обнаружь `/audit-workflow` либо штатный ID, загрузи `references/preflight.md`; сохрани версии и фактические логи.
3. На отдельной синтетической фикстуре выполни аудит; сохрани JSON-состояние, Markdown, сводку этапов и SHA-256 неизменённых исходников.
4. Убедись, что без отдельной человеческой команды `ai-tool-generator` **не создаёт** файлы.
5. Сверь результаты с критериями [общего плана](../README.md) и только после этого отметь соответствующие проверки `PASS`.

Не запускай содержимое исследуемого инструмента. Если работа с клиентом невозможна, оставь `CLIENT_NOT_TESTED`.
